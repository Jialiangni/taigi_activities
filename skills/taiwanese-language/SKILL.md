# 理解整段，再用台語寫出來

方法版本：`whole-paragraph-v1`。這份規範不綁模型、API、專案或電腦路徑。
由目前接手的寫作者完成翻譯；不因舊技能或歷史設定自行轉交 TW-Hokkien、SARC、Muse 或其他模型。
使用者明確指定外部翻譯器或要求保留其原稿時，才遵守該次分工；不得混寫後冒稱原樣輸出。

## 理解與重寫

1. **先讀完整段落及必要上下文。** 確認這段要讓讀者知道什麼、誰在做什麼、人物與代詞指誰，以及事件先後、因果、對比、否定、條件和語氣。不能看到一句就先翻一句，也不要先刪成摘要才理解。
2. **從意思重新組織台語。** 想像向台灣慣常講台語的讀者說明這件事，選擇自然的主題、敘述次序、動詞與銜接。可以分句、併句、換語序；不沿華語句型逐字替換，不要求中文每個詞都對上一個台語詞。
3. **保留原文的資訊密度與態度。** 預設漢字為主、親切清楚；正式、莊重或帶保留的原文要維持其語氣。不要自行加入熱鬧、精彩、適合親子等評價、宣傳或未支持的活動內容。
4. **按台語整句讀一次並修稿。** 檢查句子是否順、搭配是否合理、指涉是否清楚、是否仍是華語語序。助詞、俗諺、生僻字或臺羅的數量不是品質標準；不為「台語味」硬加語尾，不把某一腔口當所有人的唯一說法。
5. **回到原文核對。** 逐項核對人物角色、重要內容、分場差異、先後因果、肯否定、限制、數量與費用；段落重組不能改變關係。這是同一寫作者的修稿與自檢，不另啟動評審模型，也不要求使用者逐筆審定。

理解筆記只需保留對交接有用的簡短事實、疑點與用語決定；不用輸出思考過程或冗長逐句分析。
來源含糊時保留其不確定性；指涉或事實無法確定且會影響譯意時，標明該處待確認，不猜測補齊。

## 固定資料與專案用語

- 官方標題、姓名、機關、作品、地點、地址、日期、時間、金額、單位與URL按原文保留。人物的職務、後場／前場等角色不能因簡化而換掉。
- 要求摘要時，先理解全文，再重寫短版；不能直接截斷長稿、漏掉主角或參加限制。需要長短兩版時共用同一份理解，避免重複讀整份背景。
- 只套用使用者或目前專案已確認、且適用於本語境的用語。網站介面偏好不是所有專案的通用台語規則。
- 原文、模型草稿與使用者修訂可分版保存。只有使用者確實確認的內容才記為偏好；試譯不標成母語者審定。

## 不確定的詞先查

優先用可用的 `lookup_taiwanese`；或專案提供的同源字典命令。查整詞及符合上下文的義項、例句，必要時才拆詞；不拼接單字讀音冒充已查證複合詞。
沒有工具時可查教育部《臺灣台語常用詞辭典》公開詞頁：https://sutian.moe.edu.tw/ 。另一環境可換成可追溯的辭典介面，不必安裝特定模型。
只送需要核對的詞；不用把整份私有文稿送去字典。查證結果要分清「查無」與服務失敗，不能拿字典華語釋義當成台語譯文。
查得到個別詞不等於整句自然。未查證的讀音不補造；未知專名保留原字。無法解決的必要疑詞留為待確認，不虛報通過。
欲宣稱現行教育部推薦字或解決版本差異時，核對官方詞頁。保留實際查詞證據，不假稱母語者審定。

## 輸出與接手

一般請求直接交付台文；有疑點才附簡短說明，不強制使用者讀核對表。
另一模型／專案接手時，讀取 [交接格式](references/handoff.md)，取得完整原文、用途、必要上下文及有範圍的用語偏好即可使用此方法。
已有專案格式時採其格式，不另包一層JSON、不猜provider或模型版本。精確模型識別不可取得時標示未知。
本技能本身不授權發送訊息、刊登、修改其他專案或呼叫另外付費的模型。
