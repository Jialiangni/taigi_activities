## 建置與檢查

僅需 Python 3 標準庫（GitHub Actions 使用 Python 3.11）：

```bash
python3 -m unittest discover -s tests -v
python3 -m crawler.collect      # 自動收集候選與逐來源狀態，尚不刊登
python3 main.py                 # 以已核實資料建置，不連網
python3 main.py --check-sources # 重查所有官方頁必要內容，失敗不覆寫產物
node tests/test_frontend.cjs    # JS、篩選與下載內容檢查（需 Node.js 18+）
python3 server.py               # http://localhost:8080
```

若 macOS 的 Python 缺少系統 CA，可以指定系統憑證：

```bash
SSL_CERT_FILE=/etc/ssl/cert.pem python3 main.py --check-sources
```

不要關閉 TLS 憑證驗證。DNS、TLS、HTTP 或公告必要內容檢查失敗時，修復問題或重新核實後再執行。

## 發布流程

GitHub Actions 每日台灣時間 03:15 啟動候選收集，完成後以 `workflow_run` 觸發核實與發布，不再使用獨立的 04:00 排程。個別來源失敗仍使用本輪已保存的完整報告；缺報告、報告過期或整體工作取消則停止。推送 `main`／手動發布亦先下載最近36小時內完成的同倉庫 main 收集結果，執行測試 → 候選核實與去重 → 重查正式來源 → 建置 HTML / ICS → 前端檢查 → 提交核實資料及產物 → 僅發布 `public/`。任何發布門檻失敗不部署；推送衝突不強推、不發布未保存的版本。GitHub 排程可能延遲，並非固定時間保證完成。

`main.py` 只讀 `data/verified_activities.json`，不再載入示範資料、固定博物館／市府活動或未驗證的 API 結果。各來源已重建為候選收集器；使用 `python3 -m crawler.collect` 執行，結果寫入 `data/candidates/`。

新增活動前，請依 `SPEC.md` 核對活動名稱、單場日期時間、地點、台語內容及費用，留下活動專頁與核查紀錄。不用官方首頁、搜尋結果或一般景點頁替代活動證據。

## 台語站信任來源（2026-09-19）

每日新增 `gameislearning` 收集器，依臺北、新北、桃園篩選 [台語站活動頁](https://www.gameislearning.url.tw/taigi.php)，再讀每個活動詳情。使用者指定頁內活動皆為台語活動，因此語言不送人工審查；日期、開始時間、地點、是否過期與跨來源重複仍逐場檢查。公告內只有純文字的 BeClass、Google Forms、ACCUPASS、OPENTIX、Linktree 等 HTTPS 網址也會抽出，正式網站詳情分開提供可點的「報名／買票」與「活動公告」。活動專頁有海報時，一併收錄原圖至活動詳情，完整顯示、不裁切，可點開原圖查看；無圖或載入失敗時不保留空白圖片區。

本次實跑14個北北桃詳情，拆出38個候選場次：22場欄位完整且未過期，已加入正式清單；10場已過期排除；2場疑似與既有活動重複而擋下；4篇缺完整場次時間的公告維持候選。後兩類不是語言審查，也不會因來源可信而猜日期或重複刊登。

後續修正：公告只有月日而缺開始時間時，會沿公告的 Google Forms／支援短網址讀公開報名表，核對表單明列年份、日期與場地後拆出編號場次。「兩場都參加」只算報名組合，不另新增活動。9/20桃園古錐ê講古已補上10:30、11:30兩場及原海報；第一場的結束時間在表單內有11:20／11:30兩種記載，因此僅刊確定的開始時間。初次補時來自公開表單；目前已加入下述多層報名頁與海報OCR備援流程。

活動探索卡片已改為精簡排版：沒有核實圖片時不留封面空間，直接呈現日期、完整標題、城市、場地與費用；主辦與完整說明可於詳情查看。

目前介面採灰白／深灰配色，城市以小色點標示；卡片頂部顯示城市、類型與公告來源。來源下拉選單依當次活動產生，可與月份複選、城市、類別、費用及搜尋交集篩選，下載 ICS 也使用相同結果。週曆按日期展開所有場次；沒有活動的日期保留於日期列。

日期、標題、台文簡介、地點與底部分隔線在同列卡片中對齊，地點文字距分隔線 8px。介面與摘要採漢字台文，標題、地點、活動詳情及 ICS 保留官方原文。翻譯存於 `data/ui_taigi.json`，以完整原始描述對應；原文更新未翻譯時會明示「簡介原文」，不沿用舊譯文。

每次成功建置另產生本地 `taigi-activities-standalone.html`，與 `index.html` 相同；樣式、程式與活動資料皆內嵌，可直接開檔離線瀏覽、篩選與匯出 ICS。單檔副本不重複提交 Git，執行 `python3 main.py` 即可重建。

預設使用深色模式，頁首「◐」可切換深淺並記住手動選擇；無儲存權限或設定無效時仍以深色啟動。日期統一使用「拜一」至「拜六」、星期日為「禮拜」，依臺灣時間判斷。

## 更新前候選核實（2026-09-19）

`python3 -m crawler.review --candidates <本輪候選目錄>` 會重新讀官方證據、輸出去重與審查報告；加 `--apply` 才合併通過者至正式清單及台文顯示對照。`data/audit/latest-candidate-review.json` 列出每筆 approved／duplicate／excluded／pending 及原因；GitHub 同時保存核實報告 artifact 14天。新資料只有在後續所有來源重查與測試通過後才提交、部署。

目前自動核實支援 OPENTIX 的單場 API 與官方 HTML 交叉檢查、ACCUPASS 明列「台語場」且完整的單一場次，以及有完整日期／時間表、全程台語且明列免費的系列場次，以及使用者指定語言可信的台語站。台語站不再判斷語言，但仍要求明確場次、北北桃地點並檢查過期與重複。ACCUPASS 搜尋本來就以每個台語關鍵字搭配臺北／新北／桃園三個城市代碼執行；候選沒刊登不等於搜尋沒找到。字幕、人物台語經歷、泛關鍵字、場次總期間不作為其他來源的自動通過證據；場次資訊、語言或費用有歧義者仍待核實。自動核實與人工核實在 verification.mode／method 區分，保留原有人工紀錄。

重複判斷包含官方場次 ID、官方頁＋起迄時間，以及跨來源正規化標題＋地點＋城市＋時間；疑似重複保留待核實。保留歷史正式紀錄供比對，同一報告重跑不會重複新增。候選全文不提交 Git，也不發布到 Pages。

## 台語站報名頁追蹤與海報文字辨識（2026-09-19）

順序固定為 **公告文字 → 公開報名頁／表單 → 海報OCR**。公告只有開始時間時也會嘗試補齊結束時間；公告已完整則不多抓海報。可讀 Google Forms 正文／場次選項、BeClass 活動說明、ACCUPASS 明確場次；可從公告的純文字網址或超連結，經短網址／Linktree再追兩層，最多6頁。只讀公開頁，不送出報名、不登入、不讀填答結果。

每一層核對活動名稱、場地及公告日期，排除報名截止日與「兩場都參加」組合。表單有衝突就保留衝突，不靠海報消除；資訊不足或無法讀取時才辨識活動專頁的原海報。OCR保存圖片指紋、引擎、辨識文字與信心值；只有高信心且年月日／時間可明確對應、與公告一致的場次才能進核實流程。公告與海報都未明列年份、看不清、欄位矛盾會保留待核實原因，不猜日期或預設兩小時。

GitHub 收集與發布工作都安裝 Tesseract 及繁體中文／英文模型，不需API金鑰。macOS可用系統Vision（第一次載入Swift模組可能較久）；引擎缺失或失敗會明列原因。Python邏輯仍只使用標準庫。真實9/20案例仍取報名表的10:30／11:30，第一場結束時間衝突保持未知，未用低信心海報覆寫。測試與來源紀錄見 `data/audit/2026-09-19-registration-ocr.json`。
